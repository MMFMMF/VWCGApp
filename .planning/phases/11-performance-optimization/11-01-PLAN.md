       Then REMOVE the three Google Fonts link tags from the `<head>`:

       - `<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />`

    3. In `src/layouts/BaseLayout.astro` frontmatter, add the same font CSS imports:
       ```
       import '@fontsource/inter/400.css';
       import '@fontsource/inter/500.css';
       import '@fontsource/inter/600.css';
       import '@fontsource/inter/700.css';
       import '@fontsource/lexend/400.css';
       import '@fontsource/lexend/500.css';
       import '@fontsource/lexend/600.css';
       import '@fontsource/lexend/700.css';
       ```
       Then REMOVE the three Google Fonts link tags from the `<head>` (same lines as MarketingLayout).

    4. In `src/styles/global.css`, verify body and heading font-family declarations still reference 'Inter' and 'Lexend'. The @fontsource packages register @font-face rules with font-display: swap by default, so no manual @font-face declarations are needed. Keep the existing:
       ```css
       body { font-family: 'Inter', system-ui, -apple-system, sans-serif; }
       h1, h2, h3, h4, h5, h6 { font-family: 'Lexend', 'Inter', system-ui, sans-serif; }
       ```
       Note: Remove 'Inter var' from font-family declarations since @fontsource uses standard 'Inter' not variable fonts. Change `'Inter var', 'Inter'` to just `'Inter'`.

    IMPORTANT: Do NOT add preload hints for fonts. @fontsource CSS handles font loading automatically, and over-preloading degrades performance. Let the browser's natural prioritization work.

    WHY self-host: Google Fonts CDN adds DNS lookup + TLS handshake + external request latency. Chrome/Safari cache partitioning means fonts are NOT shared across sites, eliminating the CDN advantage. Self-hosting saves 100-300ms on mobile FCP/LCP.

<task type="auto">
  <name>Task 2: Configure Astro build optimizations and bundle visualizer</name>
  <files>
    package.json
    astro.config.mjs
  </files>
  <action>
    1. Install bundle visualizer as dev dependency:
       ```
       npm install --save-dev rollup-plugin-visualizer
       ```

    2. Update `astro.config.mjs` to add build optimizations:
       - Add `import { visualizer } from 'rollup-plugin-visualizer';` at the top
       - Add `build: { inlineStylesheets: 'auto' }` to the Astro config (inlines CSS files < 4KB automatically, reducing request count)
       - Add `rollupOptions.output.manualChunks` function to the existing vite config to split vendor bundles:
         ```javascript
         manualChunks: (id) => {
           if (id.includes('node_modules/react/') || id.includes('node_modules/react-dom/')) {
             return 'react-vendor';
           }
           if (id.includes('recharts') || id.includes('react-circular-progressbar')) {
             return 'charts';
           }
           if (id.includes('@radix-ui')) {
             return 'radix-ui';
           }
         }
         ```
       - Add visualizer to vite plugins array (alongside existing tailwindcss()):
         ```javascript
         visualizer({
           open: false,
           filename: './dist/stats.html',
           template: 'treemap',
           gzipSize: true,
           brotliSize: true,
         })
         ```

    3. Add `test:perf` script to package.json scripts:
       ```json
       "analyze": "astro build && echo 'Bundle report: dist/stats.html'"
       ```

    IMPORTANT: Do NOT set cssCodeSplit manually — Astro handles this. Do NOT set inlineStylesheets to 'always' — 'auto' is correct (only inlines small files).

    WHY manualChunks: Splitting react-vendor (~140KB), charts (~100KB), and radix-ui (~50KB) into separate chunks enables better caching — vendor code changes rarely, so returning users load from cache while only fetching changed app code.

    WHY inlineStylesheets: 'auto': Eliminates extra HTTP requests for small CSS files (< 4KB) by inlining them directly into HTML. Reduces waterfall depth on mobile.
  </action>
  <verify>
    1. Run `npm run build` — build succeeds, no errors
    2. Check `dist/stats.html` exists (bundle visualizer report generated)
    3. Verify astro.config.mjs has `inlineStylesheets: 'auto'` in build config
    4. Check build output for separate chunk files (react-vendor, charts, radix-ui)
  </verify>
  <done>
    astro.config.mjs configured with inlineStylesheets: 'auto', manualChunks vendor splitting, and rollup-plugin-visualizer. Build produces separate vendor chunks and generates dist/stats.html bundle report. Build time and output verified.
  </done>
